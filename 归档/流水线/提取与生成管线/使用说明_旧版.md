# 实验脚本管线 V2.0 · 详细使用说明

目录入口见 [README](README.md)，辅助工具的新位置见 [脚本索引](脚本索引.md)。
可使用 `python 实验.py --help` 查看主流程命令；下文保留的 `python 脚本/...` 命令仍然有效。

Python 3.10 及以上。在解压后的本文件所在文件夹打开终端。以下 `python` 在部分 Mac 上写作 `python3`。首次运行：

```
python -m pip install -r requirements.txt
python 测试.py
```

联网步骤使用环境变量 `DEEPSEEK_API_KEY`，可选 `DEEPSEEK_BASE_URL`。不要把密钥写进脚本或发给其他成员。Windows PowerShell 设置 `$env:DEEPSEEK_API_KEY="自己的密钥"`；Mac 设置 `export DEEPSEEK_API_KEY="自己的密钥"`。

## 本版固定口径

- S 为核心文本；M/L 为核心前后各 100/200 字符，沿用这次提供的方案。定位失败退回 S 并列出条目，不能当成已完成扩展。
- B/C 允许跨层语义匹配，采用“实验脚本管线整理”的口径。等义、任一方向蕴含都记 1；每条配对每轮最多一票。
- 默认每个比较跑 10 轮、主阈值 6 票、对照阈值 4 票。`实验设置.json` 在实验开始前统一确定，各条件一致；未完成全部轮次，不输出正式聚合。
- A 绑定全部 M 名册。它表示全篇史料范围，不表示每条史料都在正文实际使用；实际使用从段落引用和 C.sources 检查。A 命题及涉及 A 的边保留在树中，但不计入 ACI/SCI，避免固定赋予的连接抬高结果。
- ACI = 人类参考树中被覆盖的 B/C 节点数 ÷ 参考树 B/C 节点数。
- SCI = 两类已覆盖边的合计数 ÷ 两类参考边的合计数。两类为：① B/C→M；② B/C 节点间由 parent 明示的直接父子边。不把祖孙路径增算成边，不把两类覆盖率简单平均。另报两类的分母、命中数、覆盖率和命中清单。
- B.sources 为其子树 C.sources 的并集；B→M 是本编码图中的显式边，包含继承绑定，不声称每条都是独立语义证明。C.sources 保留段落直接引用及人工确认的绑定。纯史料段的候选归属待人工确认，不能自动当成已证实关系。
- 对齐后的论点→M，须使用完全相同的 M 身份；论点→论点，须两端均匹配，且模型中存在同方向直接边。每条参考边最多记一次；无参考边返回 null。
- 不同 SCI 定义的历史数值不能与本版混用。人类树是参考输出，不作为历史解释正确性的金标准。

## 路线一：用已有树重新测量

例如检查本次复现包中的 A05：

```
python 脚本/导入已有.py "原复现包/实验数据/A05" A05
```

把第一个路径换成实际路径。默认导入人类基准及 Q_run_2_S、A_run_2_S；其他 run 可用 `--runs 人类目录名,模型目录名`。此操作复制输入，更新 A 全量绑定、B 并集和统计，不修改原包，也不复用不同口径的历史配对。输入树及节点文本请先审阅；输入变更必须在对齐前完成。

之后运行：

```
python 脚本/_整树LLM对齐.py --paper A05 --runs Q_run_2_S,A_run_2_S
python 脚本/频次聚合.py 实验数据/A05/03_实验输出/Q_A_实验/Q_run_2_S
python 脚本/频次聚合.py 实验数据/A05/03_实验输出/Q_A_实验/A_run_2_S
```

结果在各 run 的 `频次聚合.json`：`main` 为主指标，`robustness` 为对照，`threshold_scan` 为各阈值结果。当前设置为每个比较 10 轮对齐；网络错误或格式错误可能增加调用次数。以 `实验设置.json` 为准。

## 路线二：开展新论文实验

### 1. 准备材料

已有审核完成的 `source_pool.json` 可直接放进 `实验数据/论文编号/02_史料池/`。所有条件使用同一份固定编号的史料名册。若从手工材料表开始：

```
python 脚本/手工整理.py 材料模板 材料.csv
```

用 Excel 打开后填写：`original_id`（稳定唯一编号）、`title`（书名）、`dynasty`、`volume`、`source_full`（出处）、`text`（完整核心）、`context`（核实过的连续上下文）。保存为 CSV UTF-8。脚本不会代替原典核实，不自动猜测拆分条目的身份。

```
python 脚本/手工整理.py 材料导入 材料.csv 实验数据/P01/02_史料池/source_pool.json
python 脚本/派生SML史料池.py 实验数据/P01
```

先处理输出的退化条目，再将数据用于正式上下文变量实验。M/L 文本不同不意味着史料身份不同。

### 2. 生成论文

```
python 脚本/Q条件生成.py 实验数据/P01 1 "该论文的中性研究问题" S
python 脚本/A条件生成.py 实验数据/P01 1 S "该论文的给定核心观点"
```

M/L 只替换档位；run 号用于独立生成重复。末尾可加 `--dry-run` 检查提示词，不调用模型；检查后先移出该 run 的试写提示词，再正式运行同一命令。已有产物不会被覆盖。重建的 A05 池沿用来源标记，需要设置 `ACK_RECONSTRUCTED_INPUTS=1`，表示将它用于新生成实验。

生成提示词沿用本次复现包的共同正文，包括至少引用 15 条的要求；本次 A 全量绑定修改不自动改变生成条件。不要用 A.sources 或名册完整性证明实际引用覆盖。

### 3. 手工整理段落、引用和标题

```
python 脚本/手工整理.py 模板 Q段落.csv
```

逐行填写一段完整文本；不要把标题和正文放在同一行。表中：

|列|填写方式|
|---|---|
|id|P1、P2……，唯一|
|type|title 或 text|
|heading_level|论文主标题 main；结论标题 0；章节标题 1/2/3；正文留空|
|text|完整标题或正文，可含单元格内换行|
|material_refs|手工确认的史料 ID，多个用英文分号隔开；无引用留空|

引用填写固定 M 身份，不填写临时的 SRC 编号；对照 source_pool 中 original_id 即可。正文中的原始引文标记无需删除。章节层级不得跳级，至少一章；结论只标一个。没有结论标题时可在结论正文前手工补一行 0 级标题，不改原正文。人类论文和模型论文按同一规则整理。脚本不自动判定标题或从正文猜引用。

```
python 脚本/手工整理.py 导入 Q段落.csv 实验数据/P01/02_史料池/source_pool.json 实验数据/P01/03_实验输出/Q_A_实验/Q_run_1_S
```

A 组同理；人类基准的目标目录为 `A_human_baseline`。名册也可直接使用已经确认的基准 `run.json`。已有 `原文_clean.json` 不覆盖，修订前先备份并移出文件。留存 CSV，人工检查文本未漏段、引用未错配。

### 4. 抽取、核对、校验

每份论文一次整篇抽取调用：

```
python 脚本/_论证树一次性抽取.py Q_run_1_S 实验数据/P01
python 脚本/_论证树一次性抽取.py A_run_1_S 实验数据/P01
python 脚本/_论证树一次性抽取.py A_human_baseline 实验数据/P01
```

输出 `run_论证树.json`。检查论点文本、父节点及史料归属，尤其 `evidence_candidates`；候选需人工确认后才加入相应 C 的 sources。小标题只是空间锚点，不自动证明逻辑支持。确认要保留的论点关系由 parent 明示。

修改后运行（每个目录都做）：

```
python 脚本/source_binding.py 实验数据/P01/03_实验输出/Q_A_实验/Q_run_1_S
python 脚本/校验.py 实验数据/P01/03_实验输出/Q_A_实验/Q_run_1_S
```

修复会保存首次修订前备份、更新 A 全量绑定及 B 的证据并集。C 的直接锚点引用会保留，不能仅删除 sources 来否定锚点引用；段落引用确有录入错误时应同时修正 paragraphs。校验通过只证明结构一致，不代替史料语义审阅。

### 5. 对齐与计分

把路线一中的 A05/run_2 换成 P01/run_1 即可。模型内部比较也可使用 `--human-run 另一模型run目录` 指定参考树；聚合时用 `--human 该参考run完整路径`。这是有方向的参考覆盖率，报告时注明参考侧。

## 中断、续跑和修改输入

每完成一轮就原子保存到 `对齐轮次/round_001.json` 等，并更新汇总。中断后重复完全相同的对齐命令，只补未完成轮次。输入树、计分设置、提示词、模型参数或目标轮数变化时拒绝续跑，以免混轮。请使用新 run 目录启动新测量，不删除锁来强行续跑。不要对同一 run 同时启动多个进程。

汇总的 `complete=true` 且完成预定轮数后才能计分。尚未完成的轮次不会伪装成主结果。当前正在请求但尚未成功落盘的一轮，断线时仍可能产生服务端费用；本地只能保证已保存的完整轮次不重复调用。

运行脚本与实验数据分别管理。分享代码时应排除 API.txt、本地密钥、原始论文及未获授权的数据；目录说明见 README。
