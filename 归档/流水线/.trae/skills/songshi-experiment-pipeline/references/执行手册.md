## P0.5 分段粒度验收（不通过不得进入 P1）

**规格：段落 = 论文自然段；每个正文自然段恰好 1 个 C 节点。**

```bash
python3 - <<'PY'
import json
from pathlib import Path
c = json.loads(Path('<ID>/00_原文/原文_clean.json').read_text(encoding='utf-8'))
md = [b for b in Path('<ID>/原始输入/full.md').read_text(encoding='utf-8').split('\n\n') if b.strip()]
natural = sum(1 for b in md if not b.startswith('#'))
proc = sum(1 for p in c['paragraphs'] if p['type'] == 'text')
mx = max(len(p['text']) for p in c['paragraphs'])
print('自然段', natural, '处理段', proc, '最长块', mx)
assert abs(proc - natural) / max(natural, 1) < 0.2, '分段粒度不达标'
assert mx < 2500, '存在超长合并块'
PY
```

不达标时用 PDF 重切：`脚本&数据/重洗_A02/rebuild_a02_clean.py`（改路径参数即可复用到其他实验）。
历史反例：A02 27 自然段→9 处理块→5 个 C；A06 →5；A09 →8。

## P2 史料池与名册

### P2.1 需要映射时（passage id 与 M id 不同体系）

用「出处全文」做相似度匹配，人工复核低分项：

```python
import difflib, json, re
from pathlib import Path

pool = json.loads(Path('数据集/史料池（主要）/B01_史料池.json').read_text())
human = json.loads(Path('B组交付包/B01/第二轮复现/run_论证树.json').read_text())
mids = human['encoding_table']['M_level']

passages = []           # 展平
for s in pool['sources']:
    for p in s.get('passages', []):
        passages.append({'src_p': p['passage_id'], 'source_id': s['source_id'],
                         'title': s.get('title', ''), 'text': p.get('text', ''),
                         'source_full': p.get('source_full', '')})

def norm(x):
    x = re.sub(r'\s+', '', x)
    return x.replace('（', '(').replace('）', ')').replace('《', '').replace('》', '')

used, mapping = set(), {}
for m in mids:
    best, score_best = None, 0.0
    for i, p in enumerate(passages):
        if i in used:
            continue
        a = norm(m['text'])[:60]
        sc = max(difflib.SequenceMatcher(None, a, norm(p['source_full'])[:60]).ratio(),
                 difflib.SequenceMatcher(None, a, norm(p['text'])[:60]).ratio())
        if sc > score_best:
            best, score_best = i, sc
    if best is not None and score_best >= 0.6:
        used.add(best)
        mapping[m['id']] = {'src_p': passages[best]['src_p'], 'score': round(score_best, 3),
                            'source_full': passages[best]['source_full'],
                            'text': passages[best]['text']}
# 未被人类引用的 passage：统一分配新 M 号（接在人类最大号之后），保证名册全覆盖
extra = [p for i, p in enumerate(passages) if i not in used]
base = max(int(re.match(r'M(\d+)', m).group(1)) for m in mids)
for k, p in enumerate(extra, 1):
    mapping[f'M{base + k}'] = {'src_p': p['src_p'], 'score': 1.0,
                               'source_full': p['source_full'], 'text': p['text']}
Path('<ID>_实验记录/映射_full.json').write_text(
    json.dumps(mapping, ensure_ascii=False, indent=2), encoding='utf-8')
```

验收：`len(mapping) == 人类引用数 + 额外 passage 数 == 史料池 passage 总数`。
低于 0.6 分的项要人工看，通常是对现代论著条目匹配不上。

### P2.2 生成 pool_text 三档（同一批引文 × 不同上下文长度）

先按 M 编号把全量条目落到 `pool_text_all.txt`（每行一条，格式
`[<ID>-Mxx] 出处：…｜引文：…`），再跑共享建档脚本：

```bash
python3 .trae/skills/songshi-experiment-pipeline/scripts/建档三档.py --id <ID>
```

规则（论文方案 line 33）：三档引文集合**完全相同**，只扩展上下文长度：
S=`引用片段`、M=`史料原文_200字`、L=`史料原文_400字`（前 200 字即 M 档）。
数据源为工作区根 `史料总库.xlsx` 工作表「史料库」。
质量门：`引用片段` 在 `史料原文_200字` 中的覆盖率 ≥ 0.7 才入池（`--min-cov` 可调），
被剔除的条目写入 `档位说明_<ID>.json`。

验收四条：

1. 三档条数相同，且 = 提示词里"共{N}条"的 N
2. `md5sum pool_text_{S,M,L}.txt` 三个值互不相同（M/L 上下文不同，故必然不同）
3. 每条目物理上单行（`grep -c . pool_text_S.txt` 等于条数），否则换行会把条目截断
4. S 档引文能在 M 档中找到（覆盖率 ≥ 0.7），M 档是 L 档的前缀

> **不要**把三档做成"不同条数的嵌套子集（40%/70%/100%）"——那是错误设计，
> 会混淆"上下文长度效应"与"史料数量效应"。

> 若史料池 passage 自带 M 编号（如 A01–A03），可跳过 P2.1 的相似度映射，
> 直接把文本按 M 编号落到 `pool_text_all.txt`，再跑 `建档三档.py`。

**生成后必须做引用规范化**（几乎所有实验都有上千处空格变体）：

```python
import json, re
from pathlib import Path
GEN = Path('<ID>_实验记录/生成轮次')
fixed = 0
for d in GEN.iterdir():
    fp = d / '论文_模型原始输出.md'
    if not fp.exists():
        continue
    t = fp.read_text(encoding='utf-8')
    t2, n = re.subn(r'\[\s*<ID>\s*-\s*(M\d+)\s*\]', r'[<ID>-\1]', t)
    if n:
        fp.write_text(t2, encoding='utf-8')
        fixed += n
print('规范化', fixed)
```

## P6 汇总与报告

```bash
python3 A10_实验记录/A7合并A10.py
python3 A10_实验记录/build_report_A10.py
python3 -m http.server 8900 &>/dev/null &
curl -s -o /dev/null -w "HTTP: %{http_code}\n" \
  "http://localhost:8900/<ID>_实验记录/<ID>_最终汇总报告/<ID>_最终汇总报告.html"
```

A-7 合并脚本会把结果写回各 run 的 `频次聚合.json` 的 `a7_merge` 字段（top2/top3/top4 × n6/n4），
**必须在建汇总 JSON 之前跑**。

汇总 JSON 的字段口径（`对齐汇总_<ID>.json`）：

> **术语与 JSON 字段名不一致（必读）**
> 计分定义 v2.0 起，正式报告术语是 **CCI（观点收敛度）/ ECI（证据结构收敛度）**，
> 但 `measurement.py` 输出的 JSON 字段仍叫 `ACI` / `SCI`，算法未改名。
> 对应关系：`ACI` = CCI，`SCI` = ECI。
> **取数用左列的旧字段名，写报告用右列的正式术语。**

| 字段 | 取值路径 | 报告术语 |
|---|---|---|
| `by_run[*].ACI_n6` | `main.overall.ACI` | CCI（主口径 k≥6） |
| `by_run[*].ACI_n4` | `robustness.overall.ACI` | CCI（稳健口径 k≥4） |
| `by_run[*].SCI_n6` | `main.SCI` | ECI（主口径 k≥6） |
| `by_run[*].SCI_n4` | `robustness.SCI` | ECI（稳健口径 k≥4） |
| `by_run[*].ACI_a7_top2_n6` | `a7_merge.top2.n6.ACI` | CCI（A-7 合并） |
| `by_run[*].SCI_a7_top2_n6` | `a7_merge.top2.n6.SCI` | ECI（A-7 合并） |
| `ACI_delta` | `ACI_n4 − ACI_n6` | CCI 敏感性 |
| 敏感性阈值 | `ACI_delta > 0.15` | CCI 敏感性阈值 |

> **易错：ECI 不在 `overall` 里。**
> CCI 是 `main.overall.ACI`，但 ECI 是 `main.SCI`（与 `overall` 平级），
> **没有** `main.overall.SCI`，写成它会 KeyError。
> CCI 另有分层值 `main.by_level.{B,C}.ACI`；ECI 无分层值。

报告里的 A10 行要用 **Q 总体均值**填 A-7 三列，不能用单个 run 的值，否则与其他实验行不同口径。
