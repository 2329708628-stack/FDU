# 坑位表（A01–A10 实证）

按出现频次排序。每条都给"症状 → 根因 → 修法"。遇到结果异常先查这里。

## 1. 引用标记空格变体（A06–A10 全部中招）

- 症状：装配后 `material_refs` 大量为空，模型论文看着有引用但统计不到。
- 根因：模型输出 `[ A10-M12 ]`、`[A10 - M12]`、`[A10-M12 ]`，装配脚本的
  `CITE_RE = re.compile(r'\[A10-(M\d+)\]')` 匹配不到。
- 修法：生成后统一跑 `re.subn(r'\[\s*<ID>\s*-\s*(M\d+)\s*\]', r'[<ID>-\1]', t)`。
  每实验实际修正 800–2200 处，属于常态，不是异常。

## 2. sed 换 ID 把历史实验换没了（A07 丢 A06、A08 丢 A07）

- 症状：报告横向对比表少一个实验；总数从"N 实验"变"N-1 实验"但没人发现。
- 根因：`sed 's/A0X/A0Y/g'` 会把 `NODES` 字典和 `for p in [...]` 里的旧 ID 一并替换，
  造成重复键被去重、列表元素互相覆盖。
- 修法：不要 sed。用 `scripts/新增实验.py`，它会按磁盘上实际存在的实验重建
  `NODES` 和两处循环列表，并打印结果供核对。手工改时改完用 `ast.literal_eval` 验证。

## 3. 统一名册的 statistics 写错层（A04）

- 症状：报告读不到名册统计，`total_unique_M` 为空。
- 根因：`encoding_table['statistics']` 而不是树顶层的 `statistics`。
- 修法：`st = t.setdefault('statistics', {})`，别写进 `encoding_table`。
  A05 及以后的脚本已修正，复用旧脚本时要确认这一行。

## 4. 人类树 B/C 层 sources 不是后代并集（A03）

- 症状：B 层节点 sources 数少于其下 C 层 sources 并集，递归校验失败。
- 修法：统一名册时强制
  `B.sources = union(所有后代 C.sources)`；
  并对 `A1.sources = full_roster_ids`（`exact_shared_roster` 要求 A1 覆盖完整名册）。

## 5. M 子编号 a/b/c 导致名册膨胀（A09、A10）

- 症状：名册 72 条，实际语义只有 65 条；人类引用与史料池对不上。
- 根因：`M18a/M18b`、`M13a…M13e` 这类同源子编号被当成独立条目。
- 修法：统一名册时 `re.sub(r'(M\d+)[a-z]*', r'\1', x)` 归一；
  但 **pool_text 生成用带后缀的正则** `\[<ID>-(M\d+[a-z]*)\]`，否则漏条目。
  注意 A10 的史料池 passage id 与 M id 不同体系，额外做了文本相似度映射（见执行手册 P2.1）。

## 6. 对齐只跑了部分轮次（A09 的 AS_R1）

- 症状：`对齐轮次/` 里不足 10 个 `round_*.json`，聚合结果偏低。
- 根因：批量中途被打断，对齐器可续跑，但锁文件留下"已完成"假象。
- 修法：删 `对齐轮次/`、`对齐输入锁.json`、`整树_LLM对齐.json` 后整跑；
  必要时连跑 2–3 次直到填满 10 轮。

## 7. A-7 的排序口径在不同脚本里不一致（建报告时）

- 症状：报告里某实验的 A-7 列数值明显偏离该实验其它档位。
- 根因：报告脚本用单个 run（如 `AS_R1`）的值填总体 A-7 列。
- 修法：总体列一律用 `overall['Q'|'A']['ACI_a7_topN_n6']`（字段名旧，即 CCI）的均值，与其它实验行同口径。

## 8. 嵌套 B 层（A10 首次出现，4 层 A→B→B→C）

- 症状：担心 `_整树LLM对齐.py` 把 `B2.1/B2.2` 折叠成 `B2`。
- 实测：流水线按 `node_id` 独立识别，未折叠；`round_001.json` 中两个子节点各自有匹配。
- 处理：新实验若是多层嵌套，仍要按 P4 跑单个 run 后 **打开 `round_001.json` 人工确认**一次。

## 9. 论文长度不足 3000 汉字

- 症状：个别 run 生成 2000 字左右就 `stop`。
- 修法：删该 run 的 `meta.json` 与 `论文_模型原始输出.md`，用 `--only <RUN>` 重生成，
  再对该 run 单独做引用规范化。A09 的 AM_R2 就是这样修的。

## 10. 首次全量跑总有几个 run 不齐

- 经验分布：A04/A06/A08/A10 一次通过；A03、A07、A09 有 1–2 个 run 需补。
- 判断标准：不是"有报错"，而是"缺 `频次聚合.json`"或"对齐不足 10 轮"。

## 11. 别改模型论文

- 允许：引用标记规范化、去掉 markdown 代码围栏。
- 不允许：补写段落、改标题层级、调整论证顺序。这些会污染 CCI 的可比性。

## 12. 三档史料池从未真正分档（A03–A10，最严重）

- 症状：报告里 S/M/L 三档 CCI 有差异，但差异无规律，重复实验也复现不出来。
- 根因：三重叠加——
  1. `pool_text_S.txt`、`_M.txt`、`_L.txt` 字节完全相同（MD5 一致）；
  2. 生成脚本硬编码 `POOL = (DIR/'史料池输入'/'pool_text_S.txt')`，永远只读 S；
  3. 装配脚本虽然按 run 取档，但取到的文件内容一样。
  结果 S/M/L 退化为三次重复，档位间的差异只是 `temperature=0.7` 的采样噪声。
- 修法：`scripts/建档三档.py --id <ID>` 从 `史料总库.xlsx` 取三档（同一批引文，
  S=引用片段 / M=200字 / L=400字，覆盖率≥0.7 才入池），生成脚本按 run 第二字母取档。
- 另外注意三档设计口径本身也错过一次：早期做成"不同条数的嵌套子集（40%/70%/100%）"，
  把"上下文长度效应"和"史料数量效应"混在一起；正确口径是**同一批引文、只变上下文长度**。
- 验收：三档条数相同且 = 提示词"共N条"；三档 MD5 互不相同；每条目单行（换行会截断条目）；
  M 档是 L 档前缀。
- 已修：A03、A04（2026-10-24 从史料总库重建三档并重跑全链路）。A05–A10 仍为旧口径，
  引用其结论时须注明档位轴未生效。

## 13. 统一名册只写 et.statistics 顶层 run.statistics 被覆盖（A03 重跑时暴露）

- 症状：`校验.py` 报 `statistics.source_count_by_A不一致` / `source_count_by_B不一致`，所有 run 全部失败。
- 根因：`source_binding.py` 把 statistics 写在 **run 顶层**，而 `统一名册*.py` 只写在 `encoding_table.statistics`（et 内部）。统一名册会改 A1.sources = 全名册、B 层 sources = 子树并集，改完后 et.statistics 是对的，但 run.statistics 还是旧值。
- 修法：统一名册必须同时写两份。run 顶层（`校验.py` 读取）和 et 内部（`source_binding` 习惯）数值完全一致。
- 验：`python3 校验.py 实验数据/<ID>/03_实验输出/Q_A_实验/A_human_baseline` 必须 OK。
